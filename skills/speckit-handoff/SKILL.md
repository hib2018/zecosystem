# Approved Intent to Spec Kit

Connect the zintent Meaning Gate to the Project-owned Spec Kit Definition Pipeline without copying
or replacing Spec Kit's workflow.

## Preconditions

Require all of the following before creating a specification:

- The human explicitly requests this handoff for a named Approved Intent Snapshot.
- The snapshot is the immutable path returned by a successful `zintent approve` result, or is
  cross-referenced by fresh canonical zintent state.
- The snapshot has `schema_version: 1.0.0`, a content-addressed `snapshot_id`, non-empty
  `approved_content.items`, a human approving actor, and an eligible validation result with no
  blocking findings.
- The current Project contains `.specify/` and the official Pi prompt
  `.pi/prompts/speckit.specify.md` generated by its installed Spec Kit version.

If Project-local Spec Kit files are missing, report that `specify init --integration pi` is needed
and ask before running it; initialization mutates the Project. Do not substitute a global copy of
the prompt or initialize with `--force` without separate explicit authorization.

## Handoff

1. Read only the snapshot metadata, `approved_content.items`, and `source_references` needed for the
   specification. Do not load unrelated Intent history or repository-wide context.
2. Read the Project's `.pi/prompts/speckit.specify.md` completely and follow that version as the
   authoritative specification workflow.
3. Use the approved item statements and applicable source references as the feature description.
   Preserve meaning; do not silently add, omit, weaken, or reinterpret an approved item.
4. Record the snapshot path, snapshot ID, Intent ID, and approved revision ID as provenance in the
   generated specification or adjacent Project-owned Spec Kit metadata, using the official format
   when it provides one. Do not wrap the snapshot or create a second Approved Intent artifact.
5. When the official workflow requires a materially ambiguous choice not resolved by the Approved
   Intent, stop at its clarification boundary and ask the human. The snapshot remains evidence, not
   permission to invent scope.
6. Report the generated feature directory, `spec.md`, provenance used, checklist result, and the
   next available Spec Kit stage. Do not automatically start clarify, plan, tasks, or implementation.

## Boundaries

- Never modify the Approved Intent Snapshot or zintent store.
- Never use an unapproved Intent revision, chat summary, memory entry, or raw Human Request as a
  replacement for the Approved Intent input.
- Spec Kit owns `spec.md`, `plan.md`, and `tasks.md` in the Project repository. zintent does not plan,
  and this Skill does not create its own competing definition format.
- Project-local prompts and `.specify/` files stay Project-owned and versioned with that Project;
  this global Skill contains only the reusable handoff policy.
